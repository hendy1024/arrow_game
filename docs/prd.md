# 微信箭头消除小游戏 PRD

- 版本：V1.0
- 日期：2026-09-11
- 用途：作为第一版后续设计、开发及验收依据。
- 当前阶段：需求及交互设计整理。本次不编写游戏代码、不创建游戏项目。
- 来源：本次对话中已确认的玩法、第一版范围，以及随后给出的页面和交互设计。参考图片仅用于表达棋盘与折线箭头的视觉形态。

## 1. 产品目标

开发一个手机竖屏微信小游戏。玩家在由长短不一、方向不同的折线箭头组成的棋盘中，找到出口畅通的箭头，点击后让其像贪吃蛇一样向前移动并离开棋盘。通过逐步解除遮挡，最终清空全部箭头。

前期以学习和轻松解谜为主，点击错误不扣生命、不限尝试次数；后期通过更复杂的遮挡关系和生命限制提升难度。

## 2. 核心玩法规则

### 2.1 棋盘与箭头

- 底层按方格组织棋盘，视觉上可以隐藏网格。
- 每条箭头由头部和连续身体组成，身体可以是直线或有多个转弯的折线。
- 不同箭头不能重叠或交叉，须保留清晰可辨的间距。
- 位置、长度、转弯形状、占地范围及头部方向随机变化。
- “大小随机”指长度与占地范围变化；同一关的线宽和头部尺寸保持统一。
- 随难度提升，布局逐步接近铺满棋盘，但不得以牺牲可读性与点击准确性为代价。

### 2.2 点击与出口判断

- 点击头部或身体均操作整条箭头。
- 从头部沿当前朝向检查直到棋盘边缘的整条通道，而非仅检查前方一格。
- 通道无阻挡时可移动；存在阻挡时保持原位并反馈原因。
- 生成时排除箭头自身身体挡住其出口方向的布局。
- 点击空白区域或正在移动的箭头不扣生命。

### 2.3 移动与消除

- 头部沿当前朝向向前行进，身体沿原有路径依次跟随，尾部逐渐收走；不是整条图形平移。
- 超出棋盘边界的部分逐渐隐藏，尾部完全离开才算消除完成。
- 消除完成后，剩余箭头数减一。
- 最后一条箭头完全离开棋盘后判定通关。
- 可以连续操作互不影响的箭头；移动中的身体仍占据对应位置，通道实际腾空后才允许其他箭头通过。

### 2.4 错误与生命

- 前期：点击被挡箭头仅提示，不扣生命，不限制尝试次数。
- 后期：点击被挡箭头扣除一次机会；机会耗尽则本关失败，可重新挑战。
- 一次点击最多扣一次机会；阻挡反馈期间不得因重复触发造成连续扣除。
- 第一版不限时。
- 生命限制启用关卡、每关生命数为待调参数，不是已经确定的数值。界面暂按每关 3 次机会设计。

## 3. 关卡生成与难度

### 3.1 必须保证有解

- 每个生成的关卡均须能够清空全部箭头。
- 不得仅随机摆放后直接交付给玩家。
- 生成布局后须验证存在完整消除顺序，排除循环遮挡死锁。
- 随机生成的具体实现方式由后续开发确定，但必须满足上述结果要求。
- 重新挑战保留本关相同布局，恢复全部箭头和生命，便于玩家调整策略。

### 3.2 难度递进方向

| 阶段 | 布局特点 | 主要体验 |
| --- | --- | --- |
| 入门 | 小棋盘、短箭头、较疏布局 | 学习点击与出口规则 |
| 初级 | 箭头增多，加入简单折线 | 观察遮挡关系 |
| 中级 | 棋盘扩大，长短混排 | 连续解除多层遮挡 |
| 高级 | 高密度、复杂折线、较少直接出口 | 规划消除顺序 |
| 挑战 | 更深遮挡关系并加入生命限制 | 提高判断准确性 |

- 难度应综合棋盘尺寸、箭头数量、长度、折线复杂度、填充密度及遮挡深度调节。
- 不以单纯增加数量或无限缩小箭头作为主要难度手段。
- 各阶段的具体关卡编号、数量与参数曲线待试玩确定。

## 4. 页面结构

采用“首页 + 游戏主页面 + 弹窗”的简洁结构。

```text
首页
 ├─ 开始游戏 / 继续游戏 → 游戏主页面
 └─ 设置弹窗

游戏主页面
 ├─ 暂停弹窗
 │   ├─ 继续游戏
 │   ├─ 重新开始 → 重开确认
 │   ├─ 设置
 │   └─ 返回首页
 ├─ 清空棋盘 → 通关弹窗 → 下一关 / 返回首页
 └─ 生命耗尽 → 失败弹窗 → 重新挑战 / 返回首页
```

## 5. 页面设计

### 5.1 首页

自上而下包含：

1. 游戏名称，并预留微信胶囊区域。
2. 少量折线箭头组成的主题图案。
3. 当前闯关进度，如“当前第 8 关”。
4. 主按钮：首次进入为“开始游戏”，已有进度为“继续游戏”。
5. 底部设置入口。

第一版不设置排行榜、商城或关卡地图。教学直接在第一关完成，不设独立教学页面。

### 5.2 游戏主页面

| 区域 | 内容 | 要求 |
| --- | --- | --- |
| 顶部安全区 | 微信系统胶囊 | 不与游戏按钮重叠 |
| 第一行 | 左侧暂停，中间关卡编号 | 位置稳定 |
| 第二行 | 剩余箭头数、生命状态 | 前期显示“自由尝试”，后期显示爱心及剩余次数 |
| 中央主体 | 棋盘 | 完整显示，优先占据主要可用空间 |
| 棋盘下方 | 一行操作反馈 | 提示出现不改变棋盘位置 |
| 底部安全区 | 留白 | 避开系统手势区域 |

- 不常驻显示重新开始按钮，入口收纳到暂停弹窗。
- 视觉方向：浅色背景、深色箭头、统一线宽；具体配色和名称待视觉细化。
- 普通状态下箭头统一着色，不提前标出可消除箭头。
- 棋盘边缘可留适量视觉留白，但箭头越界部分按规则裁切，不继续显示在其他界面区域。

## 6. 交互与反馈

| 场景 | 反馈 |
| --- | --- |
| 点击箭头 | 整条短暂突出显示，立即判断出口 |
| 出口畅通 | 播放头部前进、身体跟随、逐渐出界的动画 |
| 出口被挡 | 箭头轻微抖动，最近阻挡位置短暂闪烁 |
| 前期点错 | 显示“前方有阻挡” |
| 后期点错 | 扣一次机会，显示“前方有阻挡，机会 −1” |
| 完成消除 | 剩余数减一，短音效和轻微震动 |
| 完成关卡 | 简短完成反馈后显示通关弹窗 |

### 6.1 点击准确性

- 松手时判定点击，明显滑动则取消操作。
- 有效点击范围略宽于线条。
- 多条箭头靠近时选择距离触点最近的一条，一次触摸不能操作两条。
- 对高密度布局设置可读性及触控边界，避免箭头过细、过密。

### 6.2 首次教学

1. 第一关用手势引导一条出口畅通的箭头。
2. 显示“点击箭头，让它沿方向离开棋盘”。
3. 完成首次消除后显示“先移走外面的箭头，给里面的箭头让路”。
4. 教学结束后恢复正常界面，不反复展示。

首次进入生命限制关卡时，操作前展示一次规则说明：

> 从本关开始，点击被挡住的箭头会消耗一次机会。机会用完后，可以重新挑战。

玩家点击“知道了，开始”后开放棋盘操作。

## 7. 弹窗模块

| 弹窗 | 内容 | 操作 |
| --- | --- | --- |
| 暂停 | “已暂停”及设置入口 | 继续游戏、重新开始、返回首页 |
| 重开确认 | “重新开始本关？当前消除进度将重置。” | 继续游戏、重新开始 |
| 通关 | “第 X 关完成”“所有箭头已清空” | 主按钮下一关，次按钮返回首页 |
| 失败 | “本次机会已用完”“再试一次，先观察出口” | 主按钮重新挑战，次按钮返回首页 |
| 设置 | 音效开关、震动开关 | 完成 |

- 弹窗展示期间不响应棋盘操作。
- 暂停后返回应保持原有棋盘及生命状态。
- 失败重新挑战恢复本关初始状态，不更换布局。

## 8. 进度保存与中断恢复

- 保存闯关进度及未完成关卡的棋盘、剩余箭头和生命状态。
- 返回首页、切换到后台后再次进入，可继续当前关卡。
- 中断发生在移动动画期间时，恢复到一次操作完成后的稳定状态，不能出现残缺箭头或数量不一致。
- 音效、震动设置需要保留。
- 第一版不要求账号体系或跨设备同步。

## 11. 核心验收标准

1. 点击任意箭头头部或身体均可准确操作整条箭头，一次点击不会同时触发两条。
2. 仅头部到边界整条通道畅通时允许移走；存在远处阻挡也不能错误放行。
3. 折线箭头按身体路径跟随移动，不整体平移；尾部完全出界后才更新消除计数。
4. 生成关卡无重叠交叉、自身堵塞出口或不可解的循环遮挡，存在完整清空顺序。
5. 前期错误不扣机会；后期每次有效错误最多扣一次，空白点击不扣机会。
6. 生命耗尽进入失败状态，清空棋盘进入通关状态；弹窗期间不能继续操作棋盘。
7. 重新挑战恢复同一布局、完整箭头和初始生命。
8. 返回首页或后台后恢复进度一致，不丢失生命状态，不出现残缺箭头。
9. 手机竖屏下棋盘清楚、按钮可点、布局不与微信胶囊及系统手势区域冲突。
10. 前期自由尝试与后期生命规则在界面上区分清楚，首次规则切换有说明。

## 独立挑战模式（2026-09-12）
主页与普通闯关并列显示挑战模式入口，无需解锁。每局直接采用第30关档：20×20满棋盘、4块石块、3次容错，时间固定90秒。生成完成后显示规则说明，点击开始挑战才计时；支持放大拖动、暂停及后台冻结。失败重试同一布局并恢复90秒与3次机会，胜利可再挑战一张随机棋盘。
普通闯关和挑战相互独立。进入挑战前保存普通关卡，挑战不会解锁或覆盖普通进度；退出至主页或重新打开游戏结束本轮挑战，回到普通进度。声音与震动偏好共用。挑战设置中不显示重置普通进度入口。

## 挑战解锁及三种道具（2026-09-12，取代挑战无门槛入口）
挑战模式在普通闯关通关第19关、解锁第20关时开启，并弹出一次解锁提示；未达到时主页标示20关解锁。提示确认状态随存档保存，重置普通进度会重新锁定。
普通闯关及挑战每局免费提供各1次：限时关加时30秒、有限次数关容错+1、重排剩余箭头。道具入口在游戏页左上方，道具菜单暂停计时；未限时或不限次数时对应道具不可消耗。已失败或通关不允许使用；正在移动时需等待动画结束。
重排保留剩余箭头数量、累计消除进度、石块数量、剩余时间与容错次数；从独立求解结果中保留剩余部分并复验可解。生成不足或失败时旋转当前可解布局作为保底。异步期间锁定操作，不重复扣道具。存档记录道具消耗，重载不补道具；重试本关恢复原始完整棋盘和每种道具1次。挑战返回首页结束本局，普通闯关存档独立保留。

## 竞速模式与好友、个人成绩（2026-09-12，当前规则）

本节新增独立竞速，不改变普通闯关和90秒挑战。按用户最新确认，不接入云开发、不做全服榜；保留好友榜和本机个人历史成绩。

- 入口放主页，通关第5关后开启，首次到达弹提示。重置普通进度重新锁定入口，但不删除历史成绩。
- 每轮10关。第1关从10×10中等难度开始，棋盘边长按 `round(10×2^((关数−1)/9))` 增长到20×20；最低遮挡深度按 `round(2×8^((关数−1)/9))` 增长。实际边长为10、11、12、13、14、15、16、17、19、20。前三关逐步提高覆盖率，第4关起满棋盘并限制开局仅1条可移除。全部经过独立可解性检查，包含同标准保底布局。
- 不设倒计时，不允许道具；每关3次点错机会，三次点错结束整轮。失败或主动重跑从第1关开始。支持放大拖动；竞速第1、2关棋盘较小，后续显示放大按钮。
- 准备好10关后，点击开始才累计总用时。暂停、后台及关间等待仍计时，完成第10关尾部出界后停止。切后台不会提前消除移动中的箭头。关闭游戏或返回首页结束本轮，未完成不记成绩。
- 每日与每周是两套赛道，同版本、同赛期、同关数使用固定布局种子。北京时间每日00:00刷新日赛道，每周一00:00刷新周赛道。准备页面跨期时重新准备；开跑后固定原赛期，跨期完成只保留本机历史，不覆盖新赛期好友成绩。
- 好友榜在微信开放数据域读取同玩好友托管成绩，每期按完整10关总用时从小到大排序，仅保留当前赛期、本版本数据。查看需要微信好友授权；拒绝后可点击授权重试。日、周分别存储，每页5人。
- 个人历史本机保留最近200次完整成绩，按赛期从新到旧排列，同期按用时升序；每页3条，可切换日、周。保存失败保留原数据并提示重试；历史页可以重试同步本期最佳好友成绩。
- 普通关卡、生命、剩余时间、道具和解锁进度在竞速期间独立保留，竞速不推进普通关卡。重开游戏恢复普通进度。
- 本版没有服务器校时、成绩回放验证及跨设备最佳成绩合并，属于客户端好友竞速；设备日期应保持自动设置。同版本内赛道固定，后续改变生成规则须升级竞速版本并隔离成绩。

## 箭头提速与距离加速（2026-09-12，当前规则）
所有模式基础移动速度由12格/秒提高为24格/秒。点击允许移动时，按箭头头部前方到出口剩余格数额外增加速度：每多1格增加2格/秒，例如贴边24格/秒、前方8格40格/秒。速度在本次移动开始时确定并保持，避免中途变速跳动；仍按折线身体路径跟随移动，尾部完全离开后消失。动画与倒计时胜负判定使用同一个实际速度。
竞速规则版本升级为2；新版好友榜与旧版成绩分开，本机历史保留旧成绩并标出版本，同赛期同版本内按用时排序；旧版记录不允许重传到新版好友榜。

## 棋盘下方道具与持久库存（2026-09-12，取代每局各1次）
三种道具直接放在游戏棋盘下方，使用时钟、爱心、重排箭头图标，图标卡片右下角显示当前数量。移除左上角道具菜单入口。普通闯关及挑战共用每种10个初始库存，库存保存在本机主备存档；新关卡、重试、普通进度重置以及重新打开游戏都不补充库存。旧存档首次升级初始化10个，之后按存档剩余数量恢复。
点击直接使用：加时每次+30秒，容错每次+1，重排保留剩余箭头数量与当前资源且验证可解，成功后扣1个。每种可在库存范围内多次使用。非限时关点击加时、无限机会关点击容错只显示说明、不消耗；移动中等待结束后使用，重排期间锁定重复操作。数量0时点击弹出“道具已用完”，确认返回游戏；失败或通关后不可使用。竞速继续隐藏并禁用所有道具。
本机库存不提供跨设备同步，清理小游戏数据后的恢复不在本版范围内。

所有弹窗支持点击框外空白关闭，点击框内非按钮空白不关闭且不穿透操作棋盘。重置/重开确认框按取消处理；暂停及道具提示关闭后恢复原游戏；规则说明按确认处理，开局准备取消则返回主页；通关/失败结果关闭后返回主页。异步准备、重排取消后，晚到结果不能重新打开页面或扣道具。

## 排行榜授权与本人展示（2026-09-12，当前规则）
排行榜面板扩大到安全区内，左右留12像素；每日/每周改为64像素宽的小胶囊，保留44像素点击高度。列表随屏幕高度增加显示条数，右上角增加关闭按钮，外部空白关闭仍有效。
进入好友榜先查询授权状态，不自动反复弹授权。未授权时提示点击独立“好友授权”按钮；首次点击请求 scope.WxFriendInteraction，拒绝后再点进入微信设置；已授权时按钮显示“权限设置”。另有独立刷新与翻页按钮。
本人托管成绩使用开放数据域 getUserCloudStorage 单独读取，不依赖好友列表是否包含本人；好友榜底部固定“我”的成绩区域。已同步显示本期最佳用时；本机有更好成绩而托管未更新时提示待同步，引导到个人榜同步；未完成本期10关显示说明；读取失败显示重试提示。未获好友授权时仍可读取本人托管成绩。日、周以及竞速版本继续分别过滤，不伪造未完成者分数。
补充：如果本期只存在旧竞速版本的历史成绩，“我”的区域说明旧成绩保留在个人榜、新版需重新完成10关；不会把旧速度规则成绩混入新版好友榜。

## iPhone好友授权入口修正（2026-09-12，当前规则）
用户真机反馈“好友授权”直接进入只有个人信息使用记录的设置页。旧逻辑将任意 authorize 失败记成拒绝并在下次直接打开设置，无法区分隐私声明、接口错误和真正未开启权限；现改为：点击先调用 requirePrivacyAuthorize（基础库支持时使用微信默认隐私弹窗），成功后请求 scope.WxFriendInteraction。任何阶段失败均保留阶段与原始 errMsg，并弹出失败说明。
只有重新查询 getSetting 明确返回该权限未开启时，失败说明才提供“去设置”；仍需用户主动确认后打开，按钮本身不直接跳设置。未知错误不当作用户拒绝，隐私失败不继续请求朋友关系，重复点击及关闭后晚到回调受保护。授权成功后直接刷新好友数据。
代码修正和自动测试不能证明该 AppID 后台声明已配置或真机已授权；需核对后台用户隐私保护指引，以及重新预览后的真实返回结果。

### 日周难度独立配置（当前规则）
每日与每周分别读取 config/race-difficulty.json 的5关参数，支持棋盘大小、最低遮挡层数、开局最大可移除数、最大箭头长度与最低箭头数。默认每日12—16格、每周14—20格。修改JSON后构建即生效，构建验证参数并生成对应可解保底；不合理配置拒绝构建。成绩版本从有效参数自动计算，不混合不同难度成绩。操作说明见 config/README.md。

### 固定普通关卡、总览与首通奖励（当前规则）
100关配置存于 config/campaign-levels.json，运行时直接读取完整布局。每20关一页，共5页；主页总览入口、曲线路线、待通关小人、锁定/已通关状态及奖励领取标记。每完成20关开放下一页；可重玩已通关关卡，未解锁关可查看详情。最后一关完成后返回总览。
奖励由关卡rewards配置，支持time/life/shuffle不同数量。首通自动发奖，领取记录随库存与进度一起保存；重玩和重置普通进度不能重复领取。旧存档已通关关卡不补发奖励。普通道具库存支持奖励累积超过初始10个。
每关详情显示当前布局版本的个人最快用时；只统计未使用道具、计时有效的对局。纪录随本机存档保存，布局变更后独立比较。旧存档与动画中断恢复对局不参与最快纪录。
构建检查100关可解、编号与奖励配置；新增浏览器选关、翻页、奖励弹窗，以及奖励去重/恢复/重置、个人纪录、各屏幕点击区域测试。配置说明见 config/普通关卡配置说明.txt。
