# 微信箭头消除小游戏：第一版开发执行计划

- 日期：2026-09-11
- 需求依据：[prd.md](./prd.md)，V1.0。
- 本文用途：规定开发顺序、任务产物、实现边界与验收方法。
- 当前仅编制计划，不初始化项目、不编写游戏代码。
- PRD 的玩法与范围优先；本文新增的技术约定和试验参数均为执行建议，不冒充用户已经确认的产品要求。

## 1. 交付目标与执行原则

交付一个能在微信小游戏环境运行、可在手机上完整试玩的第一版：进入首页、学习规则、消除箭头、通关进入下一关、体验后期生命限制、失败重试，并在退出后恢复进度。

执行顺序：规则正确 → 移动正确 → 生成有解 → 页面闭环 → 保存恢复 → 微信真机验收。

- 先用固定测试棋盘验证玩法，再接随机生成，避免两个问题互相干扰。
- 每个阶段达到退出条件后才进入依赖它的阶段。
- 未确定参数集中配置；调参数不应修改核心逻辑。
- 不加入广告、付费、排行榜、道具、撤销、缩放、账号等 PRD 排除内容。
- 本地和真机验证通过不等于已经发布；提交审核与公开发布是后续单独执行步骤。

## 2. 开发前的技术决定

### 2.1 技术准备任务

正式开发第一天完成并记录在技术说明中：

1. 核对开发机器上微信开发者工具、目标小游戏项目类型与可用运行环境。
2. 查阅当时的微信官方文档，核实竖屏、画布、触摸、胶囊与安全区、存储、前后台、音频、震动及真机预览接口。
3. 选择渲染实现，并固定工具及依赖版本；优先评估单画布二维绘制是否满足本项目。仅在验证确有必要时引入游戏引擎。
4. 记录启动、检查、构建、导入微信开发者工具的准确命令与路径。
5. 在首次真机预览前确认可使用的小游戏 AppID 与开发者权限。缺少权限时标记真机验收受阻，仍可推进独立规则与本地验证；不能把模拟器结果当作真机结果。

技术选型不是本次计划已经完成的工作，不假定现有目录中有游戏项目。

### 2.2 建议的职责划分

| 模块 | 职责 | 不应承担 |
| --- | --- | --- |
| domain / board | 格子、箭头路径、占用、出口判断 | 绘制和平台接口 |
| domain / session | 点击结果、生命、剩余数、通关失败 | 动画帧绘制 |
| movement | 路径推进、当前占用、出口预留 | 页面导航 |
| generation | 种子随机、候选布局、可解验证、难度指标 | 玩家输入 |
| rendering | 棋盘、箭头、裁切、突出与抖动 | 独立修改生命和进度 |
| input | 坐标转换、点击取消、最近箭头命中 | 重复执行游戏规则 |
| ui | 首页、游戏页、弹窗、教学 | 私自判定关卡输赢 |
| persistence | 存档、校验、版本和恢复 | 根据屏幕动画推断游戏进度 |
| platform | 生命周期、存储、音效、震动、安全区 | 核心解谜算法 |
| config | 难度和交互参数 | 分散在页面中的硬编码 |

上述是建议模块边界，不要求每一项单独建立一个包。

## 3. 开发前统一的数据与状态约定

### 3.1 关键数据

| 对象 | 必备信息 |
| --- | --- |
| Arrow | 唯一 ID、从尾到头排序的格点路径、头部方向 |
| LevelDefinition | 关卡编号、尺寸、原始箭头集合、随机种子、生成器版本、难度配置版本、生命规则 |
| Session | 关卡定义、已消除 ID、当前生命、会话状态、进行中的移动 |
| Move | 箭头 ID、原路径、延伸路径、已推进距离、移动状态 |
| SaveData | 存档版本、完整原始关卡、稳定会话快照、教学状态、设置、已解锁进度 |
| ValidationResult | 是否有效、错误类型、完整消除序列、难度指标 |

- 路径只能由上下左右相邻格点连接，不允许斜线、自交或重复格点。
- 存储完整原始关卡，不能只存随机种子；生成器更新后仍须能重试原布局。
- 渲染使用统一的棋盘坐标到屏幕坐标转换，规则不使用屏幕像素。

### 3.2 状态与事件

- 会话状态：准备、教学、可操作、暂停、通关、失败。
- 单箭头状态：静止、阻挡反馈、移动中、已消除。
- 可操作会话可以有多条互不冲突的箭头移动，不能用全局“动画中”锁死所有输入。
- 点击判断返回明确类型：空白、滑动取消、已在移动、静态阻挡、临时移动冲突、允许移动。
- 只有静态阻挡是后期扣生命的有效错误；临时移动冲突暂不执行，提示“请稍候”，避免把动画时序当作解谜错误。这是为连续操作提出的实现约定。
- 每次触摸只有一个提交事件，剩余数与通关事件只在完成消除时更新一次。
- 生命耗尽立即锁定新输入；已接受的移动完成后进入稳定失败快照，不允许其回调再次触发通关。通过终态唯一性测试验证。

## 4. 分阶段任务

估算按一名开发者顺序实施：约 17—24 个有效工作日，另留 3—5 日修复缓冲。此为工作量估算，不含等待账号权限、用户试玩反馈、素材采购或平台审核时间。

### P0：开发准备与配置约定（1 日）

前置：用户授权开始开发。

- [ ] P0-01 完成第 2 节技术核实与版本记录。
- [ ] P0-02 初始化小游戏工程、基本检查及构建入口。
- [ ] P0-03 建立模块边界、统一坐标约定与配置文件。
- [ ] P0-04 准备固定棋盘数据：直线、折线、多层阻挡、循环无解、自身挡路、边界头部。
- [ ] P0-05 提供仅开发可见的关卡选择及占用调试开关。

交付：可启动空壳、技术说明、固定样例、配置清单。

退出条件：项目可通过记录的步骤重复启动；能绘制一个固定棋盘；暂不要求页面美化。

### P1：核心规则（2—3 日）

依赖：P0。

- [ ] P1-01 校验路径连续、边界合法、头部方向一致、无交叉重叠。
- [ ] P1-02 建立格点占用索引，扫描完整出口射线并返回最近阻挡者。
- [ ] P1-03 完成点击结果分类，规则层不直接播放动画。
- [ ] P1-04 实现前期无限尝试与后期扣生命。
- [ ] P1-05 实现消除完成、失败、通关的唯一事件。
- [ ] P1-06 实现同布局重试与会话重置。
- [ ] P1-07 完成核心规则单元测试。

必测：四个方向、贴边出口、近处空而远处被挡、折线身体阻挡、自身挡路、空白点击、重复完成回调、最后一次生命。

交付：可独立运行的规则模块及测试结果。

退出条件：固定样例判断全部符合预期；规则无需依赖微信或渲染环境即可验证。

### P2：绘制、触控与蛇形移动（3—4 日）

依赖：P1。

- [ ] P2-01 绘制统一线宽的直线、折线与箭头头部，正确裁切棋盘边界。
- [ ] P2-02 计算触点到箭头身体线段及头部的距离，在容差内选最近目标；等距时按固定规则选一条。
- [ ] P2-03 使用按下和松开位移取消明显滑动；处理触摸取消与多点触摸，防止额外提交。
- [ ] P2-04 以“原路径向前延伸，等长度身体窗口随距离推进”实现蛇形跟随。
- [ ] P2-05 根据当前身体位置更新占用，只有实际离开的区域才释放。
- [ ] P2-06 对已接受移动的出口通道预留，阻止其他移动新进入同一通道；不冲突的移动可以同时执行。
- [ ] P2-07 静态阻挡播放突出、抖动和最近阻挡位置闪烁；移动冲突只等待，不扣生命。
- [ ] P2-08 接入完成事件，尾部完全出界后减少计数。

必测：长折线路径、不同帧率推进一致、互不影响的双移动、出口交叉、尾部刚释放位置、移动箭头被再次点击、边缘触摸。

交付：固定棋盘可交互演示，录制折线移动与并行动画样例。

退出条件：能手动清空固定关卡；无整体平移、穿越、提前释放占用、重复计数或动画永久卡住。

### P3：随机关卡与可解验证（3—4 日）

依赖：P1；最终可视检查依赖 P2。

- [ ] P3-01 接入可复现的种子随机数，记录种子和生成器版本。
- [ ] P3-02 生成连续不自交的路径，控制长度、转弯和方向分布。
- [ ] P3-03 使用逆向加入构造候选：新箭头加入时能在现有布局中直接移走；最终按加入的逆序可得到一条解。
- [ ] P3-04 每次加入检查重叠、自身出口与边界，不能只验证头部。
- [ ] P3-05 用独立验证器重新计算实际布局的完整消除顺序，不能直接把构造顺序当验证结果。
- [ ] P3-06 验证器反复移除出口畅通的箭头；仍有剩余却无箭头可移除时判无解，并记录阻挡关系。
- [ ] P3-07 计算填充率、初始可移除数量、平均长度、转弯数与遮挡层数；筛选符合目标难度的候选。
- [ ] P3-08 设置尝试次数与耗时上限；失败时使用同难度已验证候选或保底布局，不向玩家交付未验证棋盘。
- [ ] P3-09 将生成拆成可让出主循环的任务，避免冻结操作或加载画面。
- [ ] P3-10 每个难度档验证至少 200 个种子，共不少于 1000 个样本；失败种子进入回归集。

说明：静止布局中，移除一条合法箭头只会减少遮挡。因此完整验证可以逐步移除任一合法箭头，不需要承诺复杂的分支搜索。难度主要来自识别遮挡和减少点错，而不是选错一个合法消除顺序导致永久死锁。

逆向构造若无法兼顾密度与难度，先调整路径采样、重试与筛选策略；所有替代生成方法仍须通过独立验证器。

交付：生成器、验证器、五档候选关卡、批量验证报告、保底布局。

退出条件：交付候选全部有解；无重叠、自身堵塞或不可复现问题；报告记录生成耗时、重试率、保底率和难度分布。

### P4：页面、教学与生命闭环（2—3 日）

依赖：P2、P3。

- [ ] P4-01 首页：名称占位、主题图案、当前关卡、开始/继续、设置。
- [ ] P4-02 游戏页：暂停、关卡编号、剩余数、自由尝试/生命、棋盘与固定反馈区。
- [ ] P4-03 实现暂停、重开确认、通关、失败及设置弹窗。
- [ ] P4-04 处理弹窗层级和输入拦截；关闭设置返回原来的首页或暂停弹窗。
- [ ] P4-05 第一关使用受控、已验证布局完成点击教学，保证引导目标存在且可移走。
- [ ] P4-06 首次进入生命关先说明规则，确认后才接受操作。
- [ ] P4-07 接入下一关、同布局重试和返回首页。
- [ ] P4-08 确保普通箭头不暴露解法或默认高亮可移除目标。

交付：可从首页连续体验的完整界面流程。

退出条件：从首次启动到教学、通关、生命失败、重试全程无断点；没有确认弹窗穿透或重复进入下一关。

### P5：存档、生命周期与设置（2—3 日）

依赖：P4。

- [ ] P5-01 保存完整关卡定义、稳定会话、生命、教学标记、设置和进度。
- [ ] P5-02 在扣生命、移动接受/完成、通关和设置变更等关键节点维护可恢复数据。
- [ ] P5-03 动画期间保存“已接受移动全部完成”的稳定快照；前台显示仍等尾部离开才更新计数。
- [ ] P5-04 返回首页或切后台时完成快照整理，停止帧循环和声音；不依赖退出通知作为唯一保存时机。
- [ ] P5-05 暂停只冻结游戏时间，恢复时不把暂停时长计入移动距离。
- [ ] P5-06 校验存档版本与内容；损坏时尽可能恢复原关卡初始状态并提示，不伪造已通关进度。
- [ ] P5-07 实现音效与震动设置；能力不可用时安静降级，不影响游戏。
- [ ] P5-08 处理保存失败的可见提示与重试，不宣称已保存成功。

交付：存档格式说明、生命周期实现、恢复测试记录。

退出条件：在扣生命、单箭头移动、多箭头移动、最后一条出界、失败和通关弹窗等节点中断，恢复后均保持一致；同布局重试不受版本或随机数影响。

### P6：参数调试、真机适配与最终验收（4—6 日）

依赖：P5、真机预览条件具备。

- [ ] P6-01 按第 5 节试验配置建立连续试玩关卡。
- [ ] P6-02 检查小屏、长屏、刘海/挖孔和底部手势安全区。
- [ ] P6-03 在至少一台 iOS 和一台 Android 真机验证；其中至少一台为可获得的较低性能设备。设备缺失须如实记录未验收项。
- [ ] P6-04 真机采样移动帧耗时、点击反馈延迟、生成耗时与连续闯关内存表现。
- [ ] P6-05 调整密度、线宽、命中容差、移动速度与反馈时长。
- [ ] P6-06 试玩观察玩家是否理解通道、是否因密度误点、生命限制是否过早；确定首发参数。
- [ ] P6-07 用最终参数重新验证实际交付候选，并回归与变更有关的测试。
- [ ] P6-08 关闭生产中的解法、占用图和开发跳关入口。
- [ ] P6-09 整理启动说明、构建产物、真机记录、已知问题与需求验收表。

交付：第一版可预览构建及交付文档，不默认公开发布。

退出条件：PRD 的 10 条验收标准全部有证据；无已知无解关卡、穿越、重复扣生命、存档丢失等阻断缺陷。

## 5. 为开发提供的试验参数

以下只用于建立可运行的开发基线，允许通过试玩调整，不是正式关卡承诺。

| 项目 | 试验起点 | 调整依据 |
| --- | --- | --- |
| 试玩关卡 | 30 关 | 先覆盖完整阶段和生命切换，不代表首发总量 |
| 入门 | 第 1 关教学，6×6 | 能看懂出口与折线跟随 |
| 初级 | 第 2 关，8×8 | 可观察到简单遮挡链 |
| 中级 | 第 3—5 关，10×10 | 多层遮挡且仍好点击 |
| 高级 | 第 6—10 关，12×12 | 提升密度与遮挡深度 |
| 挑战 | 第 11—30 关，优先保持 12×12；第 21 关起扣生命 | 优先增加关系复杂度，避免无限缩小 |
| 生命 | 第 21 关起，每关 3 次 | 检查误触和失败原因后再确定 |
| 填充率 | 入门 35%—50%，逐步到挑战 75%—85% | 指占用格点比例，须服从触控和可解要求 |
| 移动速度 | 每秒约 12 格 | 看清跟随过程，长箭头等待不过久 |
| 阻挡抖动 | 约 200 毫秒 | 反馈清楚且不造成连续扣生命 |
| 文字反馈 | 约 1 秒 | 可读且不堆叠 |
| 点击容差 | 不超过相邻平行线间距的一半，初值再按真机调节 | 兼顾易点与不误选 |

箭头数量、长度上限和转弯分布在 P3 的候选报告中确定；不同时硬性要求数量与填充率，避免生成器为满足矛盾条件无限重试。

待 P6 结束，将最终参数回写 PRD 或单独的关卡配置说明。未完成真机试玩前不把这些试验数值标记为最终确认。

## 6. 测试和验收矩阵

| 编号 | 场景 | 预期 | 验证方式 |
| --- | --- | --- | --- |
| T01 | 四方向无遮挡，含头部贴边 | 均可移走 | 规则测试 |
| T02 | 紧邻空格但远处有阻挡 | 不移动，返回最近阻挡 | 规则测试 |
| T03 | 断裂、斜线、交叉、自挡路径 | 拒绝关卡 | 数据校验测试 |
| T04 | 多转弯长箭头移动 | 身体跟随，尾部出界后计数 | 路径测试与目视 |
| T05 | 两条无冲突箭头连续点击 | 可并行，不重复完成 | 集成测试 |
| T06 | 动态出口交叉或尚未释放 | 不穿越，暂缓且不扣生命 | 集成测试 |
| T07 | 空白、滑动、移动中目标、多点触摸 | 不产生额外操作或扣命 | 输入测试与真机 |
| T08 | 前期点错、后期快速重复点击 | 前期不扣，后期每次有效输入至多扣一 | 会话测试 |
| T09 | 生命耗尽时尚有移动 | 终态唯一，无失败后又通关 | 状态测试 |
| T10 | 每档 200 个随机种子 | 合法且有完整解；失败可追溯 | 批量验证 |
| T11 | 重试、退出再进入、生成器版本改变 | 保存的原布局不改变 | 存档测试 |
| T12 | 动画、扣命、通关临界点中断 | 恢复稳定、计数生命一致 | 注入中断与真机 |
