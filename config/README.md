# 调整每日和每周竞速难度

编辑 `config/race-difficulty.json`，daily 是每日竞速，weekly 是每周竞速。每组的5个对象依次对应第1至第5关。只改数字，保留英文键名、逗号与括号。

| 参数 | 含义 | 调整建议 |
|---|---|---|
| size | 棋盘边长，8—20 | 数字越大通常越难；20代表20×20 |
| minDepth | 最少遮挡层数，1—30 | 越大越难，建议先每次增减1—2 |
| maxInitialOpen | 开局最多可移除箭头数，1—20 | 越小选择越少；1最严格 |
| maxLength | 单条箭头最多占格数，3—16 | 较小通常让箭头更碎、更密 |
| minArrows | 至少多少条箭头，1—200 | 越大要处理的箭头越多，但不能超出棋盘容量 |

当前每日棋盘为12、13、14、15、16，遮挡层数4、5、6、8、10；每周为14、15、17、18、20，遮挡层数6、8、10、13、16。两种竞速均为满棋盘，5关，关间暂停计时。

修改后在工程目录执行 `npm run build`，再用微信开发者工具编译、重新生成预览码。已运行的游戏不会自动更新配置，正式玩家需要更新发布包。无需修改游戏代码或手动改成绩版本。

构建会校验参数，自动生成与新配置一致的可解保底棋盘。过于苛刻的组合可能无法生成，构建会报出对应日/周、关数及调整建议，不会降低难度标准来强行通过。修改后建议执行 `npm test` 做完整验证。

配置改变会自动换成绩版本；旧成绩留在个人历史，好友榜只比较同版本、本期成绩。因此建议在新一期开始时发布改动。
