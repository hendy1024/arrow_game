普通关卡与奖励配置说明
====================
配置文件：config\campaign-levels.json
第一版包含100个固定关卡，每20关一页，共5页。

每个对象的字段：
id：关卡编号，从1开始连续递增，不能重复。
rewards：首次通关奖励；空对象 {} 表示没有道具奖励。
board：完整棋盘，包括箭头位置、路径、方向、障碍物、机会与限时。

奖励写法举例：
"rewards": { "time": 2, "life": 1, "shuffle": 3 }
表示奖励2个加时、1个容错、3个重排道具。
time是加时，life是增加容错，shuffle是重新布局。
只写需要奖励的道具，数量使用1至1000的整数。
只改奖励时，不需要改board中的任何内容。

默认奖励：
第5关、第25关等：容错2个。
第10关等：重排2个。
第15关等：加时3个。
第20、40、60、80、100关：加时、容错、重排各3个。
若编号符合多项，整页终点奖励优先，其次15的倍数、10的倍数、5的倍数。
实际发奖完全以每个关卡rewards字段为准。

board的主要字段：
number：必须与id相同。
width、height：棋盘宽度与高度。
arrows：箭头列表；id唯一，path为连续格点路径，direction为箭头方向。
obstacles：不能消除的障碍物格点。
lifeLimit：允许的点错次数，null表示不限。
timeLimitMs：时间限制，单位毫秒，null表示不限时。
建议修改布局后务必运行构建检查，避免交叉、越界或死局。

修改后：
在工程目录执行 npm run build，再在微信开发者工具中编译、生成预览码。
构建会验证全部关卡可解，并检查编号和奖励是否合法。
追加关卡需按20关一页追加，编号保持连续，最多1000关。
已有id代表原来的关卡，不要通过重新编号重复利用旧编号。

玩家规则：
主页“关卡总览”进入地图；每页显示20关。
已通关关卡可以重新挑战，未解锁关卡只能查看信息。
完成第20关后可以进入第2页，完成第40关后进入第3页，以此类推。
小人标记当前第一个未通关的关卡；全部通关后不再显示待通关标记。
完成第100关回到总览，可继续挑战已完成关卡。

奖励只按关卡编号领取一次，重玩、重置普通进度不会重复发放。
旧存档已经通关的关卡标记为已领取，不补发历史奖励。
奖励、领取记录与进度一同保存在本机；目前不跨设备同步。

个人最快用时：
仅记录未使用道具、且布局与当前配置一致的通关。
暂停及后台不计游戏操作时间；记录随当前进度保存。
旧存档或移动动画未完成时中断恢复的对局不计最快纪录，避免未实际完成动画产生偏低用时。
修改棋盘布局、机会或限时后使用独立纪录；仅修改奖励不改变布局纪录。

游戏更新后，正在进行的旧棋盘会保留用于续玩；从总览重新挑战才读取新配置。
